## Programs and majors

A **program** is a degree offering — BSIT, BSA, and so on. A **major** is a
named specialization inside a program. Students are placed at program-and-major
level.

Program codes are permanent. Courses, assignments, and evaluations all reference
them, so a code change ripples outward.

## Course scope

Every Course in the catalog has exactly one **scope**:

| Scope | Belongs to | Supports |
| --- | --- | --- |
| **General Education** | The college, not one program | Institutional Learning Outcomes |
| **Program-specific** | One program | That program's Graduate Outcomes |

Course scope is the single most consequential field on a Course. It decides:

- who may assign Faculty to it;
- which outcomes its CILOs may map to;
- which analytics evidence it feeds.

:::caution
Setting the wrong scope is the usual cause of a missing Course assignment, of a
CILO alignment workspace offering the wrong outcomes, and of a Program Head
finding they cannot see a GE Course they expected to coordinate on. Ask the
Secretary to correct the Course's scope if anything about its ownership looks
wrong.
:::

## Catalog defaults

Each Course carries default semester, term, and year level. These prefill an
assignment when someone creates one. They never rewrite an assignment that
already exists.

## Requested and Tutorial Courses

:::caution
Requested and Tutorial **Course types** are not currently implemented. The
application's Course workflows cover General Education and Program-specific
Courses only.
:::
