An **evaluation tool** is a versioned question set. Publishing one against a
Course or a program is what turns it into an evaluation.

## Institutional baseline

Authored by the **Secretary** or the **Dean**. It has no Course of its own. It is
the starting point everyone else copies, so scales and phrasing stay consistent
across the college.

## Program-owned tool

Authored by a **Program Head**, for their program. Used for Program-wide
deployments and for their program's Courses. They may derive it from a baseline
with **Save as Program Copy** or build it blank.

## Faculty-derived Course tool

Authored by a **Faculty member** from a template, bound to one Course. Editing it
changes nothing for any other Course.

## Question types

| Type | Meaning |
| --- | --- |
| **Likert** | A rating statement on a defined scale |
| **Guided Open-Ended** | A written prompt with guidance |
| **Predefined Responses** | A fixed choice list |

**Scale Descriptors** define what each point on a Likert scale means. Defining
them once and reusing them is what makes two evaluations comparable.

One CILO can carry many Likert questions — binding several statements to the same
CILO is expected, not a mistake.

## Versions

:::caution
Saving a tool records a **version**, and a published evaluation is frozen against
the version it was published from. Editing a tool afterwards creates a new version
and never alters a running or closed evaluation.

Respondents who saw one wording must not have their answers reinterpreted as if
they had seen another.
:::

A tool that has ever been published from cannot be deleted — responses reference
it. Archive it instead.

## A tool is not an evaluation

A tool on its own reaches nobody. Publishing is a separate, deliberate act by
whoever owns the target — see
[Evaluations in System CLOIE](/concepts/evaluations-and-deployments/).
