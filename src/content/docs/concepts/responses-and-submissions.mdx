## Draft

What you have answered but not submitted.

- Saved **section by section** while the evaluation is in progress.
- Visible only to you. Nobody else can see it, including administrators.
- Never counted as a response.
- Rejected by the application once the response is submitted.

:::caution
A draft is not a submission. Work sitting in a draft at the deadline is lost —
there is no late submission.
:::

## Submitted response

What you have confirmed. At the confirmation step System CLOIE re-checks required
answers and your eligibility, then writes the final answer set and flips the
response to **Submitted** atomically.

## One-response rule

Exactly one submitted response exists per evaluation assignment. It is enforced
in the database, not only in the interface:

- a **Submitted** response rejects further draft saves;
- a **Submitted** response rejects further submissions;
- a later eligibility change — the window closing, the Student becoming inactive,
  the roster changing — **never uncounts** a response already submitted.

That last point is the important one. Evidence already collected stays counted.

## Why submitted responses are locked

A program has to be able to trust that the response recorded for a term is the
response that respondent actually gave in that term. Editable submissions would
make every figure arguable.

## What happens after the window closes

- Nothing is deleted.
- Drafts simply stop being submittable.
- The response appears in the respondent's
  [submission history](/student/history/) and in the owner's review views.
