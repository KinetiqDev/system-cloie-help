The **Users** page is the institution's account list. It is the only place an
account can be created or closed.

## What the Users page shows

Each row is one person, with their current roles, status, and program
affiliations. Use **Filter users** and **Search** to narrow the list.

## Create an account

Use **New User**. Creating an account for a Student or an external respondent in
this way also records their institutional data immediately, so they do not wait
for self-service verification. See [Create a user account](/secretary/create-user/).

## Edit an account

Select **Edit user**. What you can change depends on the roles the account holds:

| Section | Holds |
| --- | --- |
| Personal Information | Name, email, contact details |
| Current roles | Which roles this account may select |
| Program and Placement | Student program, major, year level, section, academic placement |
| Managed Programs | Which programs this Program Head is an authorized Program Head for |
| Faculty Profile | Faculty-specific academic and teaching details |
| Alumni Profile | Degree and graduation details used for verification |
| Industry Partner Profile | Organization name and primary program affiliation |
| Organization and Verification | External verification state |
| Academic History and Verification | Alumni academic record |
| Data Privacy & Responses | Respondent data and privacy settings |

## Activate or deactivate an account

Deactivating stops the person signing in and revokes every role on the account.
It does not delete anything: evaluations they already submitted, responses they
already received, and their history all remain intact, because submitted
evidence is never removed by an account change.

To bring someone back, edit the account and set it to **Active** again. Their
roles and profile are still there.

## Roles and role-specific information

**Current roles** controls which roles the account *may* select. It does not
force one — a multi-role account is asked to choose an active role at sign-in.

Use **Add a role** to grant an additional role. Internal roles such as Secretary,
Dean, Program Head, and General Education Coordinator should only be granted
deliberately; granting one gives that person institutional authority over real
records.

## Account status values

| Status | Meaning |
| --- | --- |
| Active | The account can sign in and use its roles. |
| Inactive | The account cannot sign in. Nothing was deleted. |
| Pending | An external account awaiting verification. |
| Approved | A Faculty request the Secretary approved. |
| Rejected | A Faculty or external request the Secretary declined. |
