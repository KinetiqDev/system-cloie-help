Someone who signs in with an ACD email that matches no existing account can
request a **Faculty Member** role. The request waits here until you decide.

## What the page shows

Each row is one **Request received**, with the applicant's identity, the
program they asked for, and the current decision state: **Submitted**,
**Approved**, or **Rejected**.

## Approve a request

1. Open the request and confirm the applicant's identity and requested program.
2. Select the approval action and confirm.
3. The **Faculty Member** role is added to that account and marked **Approved**.

The applicant can then enter the Faculty workspace immediately, provided their
Faculty profile is complete.

## Reject a request

1. Open the request and select the rejection action.
2. Add a **Decision note** so the person understands why.
3. The request is marked **Rejected** and the account keeps whatever roles it
   already had.

A rejected request does not create a Faculty role. If the person was trying to
become a Student or an external respondent as well, those roles are unaffected.

## Why an approved request still does not open a workspace

Approval grants the **role**. It does not grant **teaching capability** — that
comes from a Course assignment. See
[What your Program affiliation means](/faculty/#what-your-program-affiliation-means).
