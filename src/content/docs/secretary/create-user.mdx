Use **New User** to create an account for someone who cannot self-register — an
internal staff member, a Student, or an external respondent the institution has
already verified on paper.

## Before you start

You need, for every role:

- the person's **full name** as their sign-in provider reports it;
- their **email address** — internal roles must use an ACD institutional address;
- the **role** the account is for.

You also need the role-specific information below. You can create the account
without it, but the person will not be able to enter their workspace until it
is present.

## Choose the user's role

Pick the one role the account is being created for. Roles can be added later
from [Manage users](/secretary/users/).

| Role | Additional information required |
| --- | --- |
| Secretary | none beyond the account |
| College Dean | none beyond the account |
| General Education Coordinator | none beyond the account |
| Program Head | **Managed Programs** — which programs this person heads |
| Faculty Member | Faculty Profile — academic and teaching details |
| Student | Program, major where required, year level, section |
| Alumni | Degree and graduation details used for verification |
| Industry Partner | Organization name, primary program affiliation |

## Enter role-specific information

Fill in the section that matches the role. For a Student, selecting a program
determines whether a major is required.

:::caution
A Student account created here is placed into the active academic term in the same
step. If **no academic period is active**, System CLOIE still creates the Student
but leaves them in deferred enrollment with no evaluations available. Set the
active period first — see [Manage school years](/secretary/academic-calendar/).
:::

External accounts created here are **institution-verified at creation**, so they
skip the pending state that self-service registrations go through.

## Review the account

Check the name, email, role, and role-specific fields before saving. The email
address is the account's identity — it is what matches a future sign-in.

## What happens next

The account is created **Active**. The person signs in with the matching email
address. If their profile is complete, they land directly in the workspace; if
not, they are taken to onboarding to finish it.

## If the email already exists

System CLOIE matches accounts by exact, normalized email address, so one person
cannot hold two accounts. Edit the existing account instead — either to fix the
role-specific fields or to **Add a role**.
